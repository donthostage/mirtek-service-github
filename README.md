# Миртек: прототип сервиса обращений

Рабочий локальный API и демоинтерфейс. Версия 0.4 реализует исходящие HTTP-запросы к отдельному моку источника: наличие по артикулу и складу с отдельным резервом, правила возвратов и жалоб, расписание, акции и условия доставки. Нормализатор перед этим шлюзом может перевести другой контракт в наши поля. В режиме AITUNNEL используется семантический разбор намерения, вида вопроса и параметров с проверкой цитат и контекста. Сервис не подключён к компании. Реальная модель без ключа ещё не проверена. Реальные KPI не измерены.

Актуальные вопросы заказчику и подтверждённые решения — `docs/OPEN_QUESTIONS.md`. Сверка полного объёма PDF — `docs/REQUIREMENTS_AUDIT.md`; ограничения семантической проверки — `docs/SEMANTIC_PARSER.md`.

## Как теперь работает источник

Наш сервис сам спрашивает API источника и проверяет ответ. Он не ждёт, что компания пришлёт обновления. Для учебного наличия: артикул 10001 и склад WH-DEMO-1. Магазин не приравнивается к складу. Для возвратов и жалоб работает поток уточнения и чтения учебных инструкций.

Подробная инструкция, контракты и границы — `docs/HTTP_PULL.md`. Проект поведения — `docs/RETURNS_COMPLAINTS.md`; исполнимые схемы — `contracts/`. Минимум пять сценариев сохраняется для итогового проекта.

## Запуск

Требуется Python 3.12 (на нём проверено) и интернет для первой установки. Из папки проекта в PowerShell:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-lock.txt
.\.venv\Scripts\python.exe -m scripts.run_demo
```

Открыть `http://127.0.0.1:8766`. Остановка: Ctrl+C в окне сервера. Авторизация и интеграции для локального демо не нужны. При занятых портах: `python -m scripts.run_demo --api-port 8866 --source-port 8867`; тогда интерфейс будет на `http://127.0.0.1:8866`.

На текущем компьютере подготовлен `start-local.ps1`: он использует уже установленные зависимости из соседней папки `work/vendor` и запускает основной сервис на 8766 и отдельный источник на 8767. Для переноса на другой компьютер используйте команды выше. Архив содержит исходники, а не Python и сторонние пакеты.

## AITUNNEL

На текущем компьютере запустите `start-aitunnel.ps1`: он запросит точный id модели и ключ скрытым вводом, затем запустит сервер. Если сервер baseline уже работает на 8766, сначала остановите его. Ключ не сохраняется в файлы. Модель выбирается пользователем из каталога AITUNNEL, обязательно с поддержкой JSON Schema; конкретная модель ещё не выбрана сравнением.

Для другого окружения задайте серверные переменные `MIRTEK_CLASSIFIER=aitunnel`, `AITUNNEL_MODEL` и `AITUNNEL_API_KEY`, затем запустите uvicorn обычной командой. `.env.example` — справочный шаблон; автоматического чтения `.env` нет. Не вставляйте настоящий ключ в команды с историей, код или интерфейс браузера.

Если режим aitunnel выбран, но ключ/модель отсутствуют, API вернёт handoff с `model_not_configured`. При сбоях модели нет скрытого переключения на правила. `/health` показывает выбранный режим и наличие настройки, но не подтверждает доступность провайдера.

Модель возвращает направление, вид обращения, тему правила и явно указанные параметры с цитатами. Сервер проверяет цитаты, получает факты из источника и программно разрешает дату. Каталог, остатки и база знаний модели не передаются. В AITUNNEL уходит текущий текст и ограниченный структурированный контекст ожидаемого уточнения. По уточнению пользователя от 23.10.2026 использование AITUNNEL разрешено без дополнительных ограничений компании; реальные обращения пока не предоставлены.

Подробности: `docs/AITUNNEL.md`, `docs/SEMANTIC_PARSER.md`; подготовка сравнения — `docs/MODEL_COMPARISON.md`.

## Что проверить в интерфейсе

1. «До скольки сегодня работает магазин на Учебной?» → часы и источник.
2. «Как работает S1?» → часы на сегодня по учебному расписанию. Закрытие 23.10.2026 — исключение только этой даты. После 31.10.2026 дата расписания не подтверждена, сервис отказывается отвечать.
3. «Есть артикул 10001 WH-DEMO-1?» → доступно 12.5 м, в резерве 2.5 м; для WH-DEMO-2 — нулевой доступный остаток. Адрес магазина без идентификатора склада вызывает уточнение.
4. «Есть товар?» → артикул → склад: уточнения продолжаются через context_id.
5. «Как оформить возврат?» → канал покупки → учебная инструкция через API источника. «Как оставить жалобу?» → учебная инструкция. Конкретная жалоба → оператор.
6. «Хочу оператора», неизвестный вопрос, несколько сценариев → handoff с явным указанием, что доставки сотруднику нет.

Все магазины, артикулы, количества и политики вымышлены. В режиме HTTP остаток помечается synthetic и действует пять минут с момента ответа мока: у 10001 на WH-DEMO-1 доступно 12.5 м из 15 м, 2.5 м в резерве. Расписание, акции и тексты правил в том же моке подтверждены до 22.11.2026 09:00 UTC+7, а конкретная дата расписания — только 22–31 октября. Старый режим snapshot читает `data/synthetic.json` с теми же учебными сроками; его остатки действуют до 23.10.2026 09:00 UTC+7. После истечения сервис отказывается отвечать. Не продлевайте срок реальных данных без нового подтверждённого снимка.

## Проверки

```powershell
.\.venv\Scripts\python.exe -m pytest -q
.\.venv\Scripts\python.exe -m scripts.evaluate
.\.venv\Scripts\python.exe -m scripts.evaluate_workflows
```

Историческая оценка baseline использует фиксированное учебное время 22.10.2026 12:00 UTC+7, поэтому воспроизводится после истечения снимков. `docs/synthetic-report.json` и `.md` — результаты учебной проверки, **не подтверждение реальных KPI**. Выборка открыта и использовалась при разработке, а не является закрытым контролем. Контрольные фразы не перебирают все возможные формулировки.

Для актуального потока есть отдельная проверка на 23.10.2026: 32 диалога, 36 шагов и шесть направлений с заранее записанными разборами. Результат — `docs/workflow-report.json`; объяснение — `docs/WORKFLOW_EVALUATION.md`. Она не обращается к настоящей модели и не измеряет её качество.
