# Шлюз источника

Имена полей ниже — контракт нашего шлюза. Нормализатор перед ним переводит API компании в эти запросы. Шлюз только читает: жалобу не регистрирует, возврат не одобряет, остаток не резервирует.

| Метод | Что отдаёт |
|---|---|
| `POST /source/v1/inventory/lookup` | `{sku, warehouse_id}` → `on_hand_quantity`, `reserved_quantity`, `available_quantity`. Клиенту называется только available, и он обязан равняться on_hand − reserved. |
| `POST /source/v1/policies/resolve` | `{scenario, topic, purchase_channel}` → текст правила. Сценарии: `returns`, `complaints`. |
| `POST /source/v1/stores/catalog` | `{}` → магазины, псевдонимы и окно подтверждённого расписания. Адрес магазина не является складом. |
| `POST /source/v1/stores/hours` | `{store_id, on_date}` → часы на дату или закрыто. Дата вне окна — `date_unconfirmed`. |
| `POST /source/v1/promotions/list` | `{on_date}` → тексты акций со `scope: all` или `restricted`. Ограниченную акцию сервис не пересказывает как общую. |
| `POST /source/v1/delivery/terms` | `{topic: delivery_terms или pickup_terms}` → текст условий. Цену и срок доставки источник не выдумывает. |

Обновление 0.4: основной сервис читает все шесть направлений через этот мок (`app/source_api.py`). Подробности — ../docs/HTTP_PULL.md.

Контракты для возвратов, жалоб и складских остатков. Решения правил используются основным сервисом через HTTP pull; отдельные examples.json по-прежнему содержат заранее заданный разбор.

- `models.py` и `*.schema.json`: схемы разбора LLM и обмена с источником правил.
- `source-openapi.json`: предлагаемый API источника; можно показать техническому специалисту компании.
- `examples.json`: девять вымышленных примеров с вручную заданным разбором, запросом к моку и ожидаемым решением.
- `mock_source.py`: источник вымышленных инструкций, без доступа к Миртеку.
- `workflow.py`: референс серверного решения; не выполняет распознавание текста и не управляет токенами диалога.
- `mock_api.py`: запускаемый HTTP-мок источника правил.

Из корня проекта с установленными зависимостями:

```powershell
.\.venv\Scripts\python.exe -m uvicorn contracts.mock_api:app --host 127.0.0.1 --port 8767
```

Документация мока: http://127.0.0.1:8767/docs. POST `/source/v1/policies/resolve`, пример тела: `{"scenario":"returns","topic":"steps","purchase_channel":"store"}`. Все ответы относятся к учебным данным; даты фиксированы. Основной клиентский сервис на 8766 — версия 0.3 и использует этот источник по HTTP.

Пересоздать JSON-схемы и примеры: `python -m contracts.export`. Проверить: `python -m pytest -q`. Эти команды не обращаются к AITUNNEL и не расходуют баланс.

HTTP-поток подключён к API сообщений. Следующие шаги — семантическое извлечение параметров с проверкой по исходному тексту и испытания выбранной LLM. Сервис пока не регистрирует жалобы, не меняет заказы и не отправляет сообщения сотрудникам.
