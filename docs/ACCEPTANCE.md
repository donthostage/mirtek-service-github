# Методика приёмки — проект для согласования

Численные пороги взяты из исходного задания; правила знаменателей и спорных случаев нужно подтвердить с компанией.

Единица оценки — завершённое обращение/диалог, а не отдельное сообщение. Закрытая контрольная выборка должна содержать реальные обезличенные обращения, даты и согласованный эталон: сценарий, параметры, допустимый ответ, достаточность источника и правильную эскалацию. Отделить от данных разработки, исключить дубликаты, зафиксировать версии источников. Разметку спорных примеров подтверждает ответственный Миртека. Отчёт должен содержать размер выборки, состав, ошибки и доверительные интервалы; маленькая выборка не доказывает устойчивые проценты.

## Метрики

1. Корректные решения / все контрольные обращения ≥90%. Решение — фактически правильный и уместный автоматический ответ либо обоснованный эталоном handoff. Нельзя улучшить показатель, передавая всё оператору: автоматизируемые запросы с необоснованным handoff считаются ошибками.
2. Фактически правильные ответы / все автоматические ответы ≥90%. Эксперт проверяет все существенные утверждения по версиям источников, применимость к вопросу, товару, магазину и дате. Неверное число, лишнее обещание или нерелевантный общий текст — ошибка.
3. Запросы с полным временем ответа API ≤5 с / все запросы ≥95%. Измерять от приёма API до готовности ответа, с вызовами модели и источников; внешние каналы исключить. Зафиксировать железо, конкурентность и нагрузку. Таймауты и серверные ошибки не исключать. Отдельно вывести p50/p95/p99 и долю ошибок. Внутренний elapsed_ms демонстрации не заменяет замер API.
4. Корректно автоматически завершённые обращения / все обращения внутри поддержанных сценариев ≥80%. Включать неоднозначные и сложные обращения этих сценариев; не выкидывать их ради процента. Уточнение само по себе не завершает обращение. Если после уточнения получен корректный ответ — автоматическое завершение; если оператор, обрыв или таймаут — нет.

Отдельно показать неизвестные запросы, ложные автоматические ответы, полноту источников и долю уточнений. Ошибки источника учитывать в общей оценке, а также показывать срез при исправных источниках. Условия обоих срезов согласовать заранее.

## Синтетический отчёт этой версии

Используется открытая учебная выборка и фиксированное время, а не реальные обращения. Проверка полного ожидаемого текста — автоматическая регрессия против учебных эталонов, не экспертная оценка на компании. Запросы отправляются последовательно через in-process HTTP-клиент без сети и модели. Это лишь проверка работоспособности контракта и методики; нагрузку и реальные сроки ответа она не подтверждает.
