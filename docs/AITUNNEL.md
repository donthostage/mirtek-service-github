# AITUNNEL: настройка и границы

Подготовлен адаптер к `POST https://api.aitunnel.ru/v1/chat/completions` с Bearer-авторизацией и `response_format=json_schema`. Основание — официальная документация, проверенная 22.10.2026:

- [Справочник API](https://aitunnel.ru/docs/api-reference)
- [Структурированный вывод](https://aitunnel.ru/docs/structured-outputs)

Поддержка схем есть не у каждой модели/провайдера; строгий режим не заменяет проверку результата на нашем сервере. Результат валидируется Pydantic, неизвестные поля, типы, сценарии и противоречия отклоняются.

## Включение

На текущем компьютере: `start-aitunnel.ps1`. Ввод ключа скрыт; скрипт не пишет его на диск. Нужны ваш ключ и точный id модели из каталога с поддержкой structured outputs. Отдельный проектный ключ с ограниченным бюджетом поможет контролировать расходы. Модель по умолчанию не выбрана, чтобы случайный запуск не использовал неизвестную стоимость.

Для другой среды: установить зависимости из requirements-lock.txt и задать серверные `MIRTEK_CLASSIFIER=aitunnel`, `AITUNNEL_API_KEY`, `AITUNNEL_MODEL`. После изменения настроек перезапустить сервер. Файл `.env.example` сам не загружается. Отмена запуска скрипта восстанавливает прежние значения переменных окружения в этом терминале.

Включение режима разрешает отправку введённого текста AITUNNEL и платные вызовы выбранной модели. По уточнению пользователя от 23.10.2026 компания разрешает AITUNNEL без дополнительных ограничений. Реальных обращений пока нет, поэтому проверки остаются синтетическими. Политики провайдера отдельно не проверялись; разрешение использовать сервис не отменяет защиты ключа и минимизации передаваемых данных.

## Что сделано

- Классификация пяти сценариев, неопределённости, запроса оператора и нескольких намерений.
- Проверяемый структурированный ответ без фактов и свободного ответа клиенту.
- Pending-сценарий для коротких уточнений без передачи полной истории.
- Обработка отсутствия настройки, таймаутов, ошибок HTTP, отказа модели, обрезанного/невалидного и слишком большого ответа.
- Никаких автоматических повторов и редиректов; при отказе провайдера — handoff.
- Раздельные режимы в `/health`, API-ответах и демоинтерфейсе.

В версии 0.4 извлечение параметров и вида вопроса выполняет семантический адаптер с проверкой цитат и контекста; дата разрешается программно. Неоднозначные и неизвестные параметры не угадываются. Свободный ответ фактами и автономные действия модель не выполняет. Подробности — SEMANTIC_PARSER.md.

## Что проверено

Автоматические проверки используют поддельный HTTP-транспорт с вымышленным ключом. Проверяются контракт запроса, схема, ошибки, утечка ключа в ответах, короткие уточнения и получение факта именно из источника. Это не вызовы реального AITUNNEL, не оценка выбранной модели и не подтверждение KPI.

Для живой проверки нужны ключ и модель: начать с нескольких синтетических запросов, сверить источник, фактический usage и задержку. Затем сравнить модели на одинаковой выборке в пределах согласованного бюджета. Открытый синтетический отчёт текущего проекта по-прежнему оценивает только baseline.
