# Получение данных исходящими API запросами

## Что работает в версии 0.4

Наш сервис сам отправляет HTTP-запрос источнику и получает данные для ответа. Направление: клиент → наш API → API источника → наш API → клиент. Источник не обязан сам присылать обновления. Никакой входящей синхронизации остатков и фонового копирования каталога в этой версии нет.

Сейчас источник — отдельный локальный FastAPI-мок. Это настоящий HTTP-обмен между двумя процессами с вымышленными данными, а не подключение к компании. В режиме HTTP наличие, правила, расписание, акции и доставка читаются из этого мока. Нормализатор перед шлюзом может подставить поля компании; имена в таблице `contracts/README.md` остаются нашими. Миртек не подтверждал, что реализует именно эти адреса.

## Запуск

На текущем компьютере запустите `start-local.ps1` в корне проекта: откроется один управляющий процесс, который поднимет оба сервера. Интерфейс: http://127.0.0.1:8766. Документация источника: http://127.0.0.1:8767/docs. Ctrl+C останавливает только запущенные этим скриптом процессы. Порты должны быть свободны.

В подготовленном Python-окружении на другом компьютере:

```powershell
.\.venv\Scripts\python.exe -m scripts.run_demo
```

Для AITUNNEL используйте `start-aitunnel.ps1`: он также запускает оба сервера. Нужны модель и ключ; вызовы LLM платные. По умолчанию локальный запуск сохраняет выбранный серверный режим распознавания; если MIRTEK_CLASSIFIER не задан, используется baseline.

Для раздельного запуска:

```powershell
# Терминал источника
.\.venv\Scripts\python.exe -m uvicorn contracts.mock_api:app --host 127.0.0.1 --port 8767
# Терминал сервиса
$env:MIRTEK_SOURCE_BACKEND = 'http_pull_mock'
$env:MIRTEK_SOURCE_URL = 'http://127.0.0.1:8767'
.\.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8766
```

## Наличие

Клиентский POST `/api/v1/availability` принимает `{"sku":"10001","warehouse_id":"WH-DEMO-1"}`. Вызывает на источнике POST `/source/v1/inventory/lookup` с тем же телом. Возвращает обычный Reply: статус, ответ, причину, источник, время проверки и `data_backend=http_pull_mock`.

Чат POST `/api/v1/messages` также вызывает этот источник. Пример: «Есть артикул 10001 WH-DEMO-1?» Если артикул или склад неясны, задаёт уточнение и сохраняет уже известные параметры. В демо доступны артикулы 10001/10002, склады WH-DEMO-1/WH-DEMO-2. Наименование товара по свободному описанию через API каталога пока не ищем: требуется точный артикул.

Контракт источника различает found, product_unknown, warehouse_unknown, stock_unknown, unavailable. При found обязательны item и source. item содержит точные sku, warehouse_id, наименования, available_quantity и unit. available_quantity — доступное количество, а не общий остаток вместе с резервом; формулу расчёта должен подтвердить поставщик данных. source содержит id, version, as_of, valid_until, synthetic.

Учебные значения доступного остатка: 10001/WH-DEMO-1 → 12.5 м при 15 м на руках и 2.5 м в резерве; 10001/WH-DEMO-2 → 0 м; 10002/WH-DEMO-1 → 4 м; 10002/WH-DEMO-2 → stock_unknown. Клиенту называется только available_quantity. Отсутствующий остаток не равен нулю. Отрицательное, нечисловое или не сходящееся количество, другая позиция/склад и неверный формат отклоняются. Магазин не приравнивается к складу; возможность самовывоза не выводится из наличия на складе.

Только у моков timestamp формируется в момент ответа и действует пять минут; это не обновление остатков компании. Настоящий источник должен сообщать время актуальности данных, а не просто время HTTP-ответа. Будущие и просроченные данные не используются.

## Возвраты и жалобы

Общие вопросы чата вызывают POST `/source/v1/policies/resolve`, например `{"scenario":"returns","topic":"steps","purchase_channel":"store"}`. В ответе — подходящая инструкция, версия, область действия и срок актуальности. Данные клиента или исходный текст в этот запрос не включаются.

«Как оформить возврат?» → источник сообщает, что нужен канал покупки → сервис уточняет → «В магазине», «На сайте» или «На маркетплейсе» → новый исходящий запрос и учебная инструкция. «Как оставить жалобу?» → инструкция из источника. Срок рассмотрения и перечень условий возврата в моке явно не заданы: число дней клиенту не называется. Конкретная жалоба или просьба решить индивидуальный возврат → handoff. Ключи не выводятся, жалобы не регистрируются, выплаты не производятся.

## Расписание, акции, доставка

`POST /source/v1/stores/catalog` отдаёт учебные магазины S1 и S2. `POST /source/v1/stores/hours` принимает `store_id` и дату и возвращает часы либо `null`, если магазин закрыт. Дата вне 22–31 октября 2026 — `date_unconfirmed`, сервис не подставляет недельный график сам.

`POST /source/v1/promotions/list` принимает дату и возвращает только акции этой даты. Строка со `scope: restricted` не попадает в общий ответ. `POST /source/v1/delivery/terms` принимает `delivery_terms` или `pickup_terms`. В учебном тексте нет цены и срока доставки. Вопрос о своей посылке, стоимости или адресе уходит оператору.

В режиме baseline тема и параметры выбираются программно. В режиме AITUNNEL используются SemanticResult, проверенные цитаты параметров и контекст; подробнее SEMANTIC_PARSER.md. Поддержка произвольных формулировок реальной выбранной моделью ещё не измерена. Необходимы реальные тексты компании и живые испытания.

## Настройки и сбои

MIRTEK_SOURCE_BACKEND: `http_pull_mock` по умолчанию; `snapshot` включает прежний локальный режим для регрессий. MIRTEK_SOURCE_URL задаётся только в серверном окружении, не в сообщении клиента. MIRTEK_SOURCE_API_KEY — отдельный ключ источника, не ключ AITUNNEL. Локальный мок не требует ключа; launcher не передаёт ему секреты провайдера.

HTTPS обязателен, кроме буквального localhost/127.0.0.1/::1. В URL запрещены встроенные логин/пароль, query и fragment. Перенаправления, прокси из окружения и автоматические повторы отключены. Ограничение ответа 64 КиБ и общий отменяемый бюджет HTTP-вызова источника 1 секунда. Время модели и источника суммируется; нагрузочный KPI требует отдельной проверки.

При ошибке, таймауте, устаревании, неподходящем или некорректном ответе — handoff с reason_code. Незаметного перехода на старые локальные остатки нет. `/health` сообщает выбранный backend, но не проверяет доступность источника. `company_connected` всегда false.

Текущий runtime принимает только явно синтетические ответы. Для подключения реального API потребуется согласовать контракт, авторизацию и семантику полей, адаптировать существующий API при необходимости и добавить режим реальных данных с корректной маркировкой. Просто заменить URL и назвать подключение готовым нельзя.

## Проверки

`python -m pytest -q` — автоматические проверки. `python -m scripts.run_demo --api-port 8876 --source-port 8877 --smoke --report docs/pull-smoke.json` — отдельные процессы и настоящий локальный TCP-обмен. В smoke запускается baseline, платных вызовов модели нет. В конце источник выключается, чтобы проверить handoff без локальной подмены данных; процессы теста затем завершаются.

OpenAPI источника: `contracts/source-openapi.json`. JSON Schema методов лежит рядом в `contracts/`. Это техническое предложение для Миртека: нормализатор приводит их ответ к этим полям.

## Уточнения после ревью 29.10.2026

Для `status=found` поля `hours` и `promotions` обязательны. Явные `hours: null` и `promotions: []` подтверждают закрытие магазина и отсутствие акций. Пропуск поля означает некорректный ответ источника, а не отсутствие факта. Ограничение отражено в JSON Schema и OpenAPI.

Общий бюджет внешнего ожидания на обращение — 4,5 секунды: модель и последовательные вызовы источника делят время. Когда оно закончилось, сервис возвращает `request_timeout`. Это не подтверждение KPI под нагрузкой.

Общие вопросы о стоимости и сроке доставки разрешены: данные берутся из ответа /source/v1/delivery/terms. Пример мока: от 300 ₽, 1–3 рабочих дня; это явно вымышленные данные для демонстрации контракта, не тариф компании. Индивидуальная цена по адресу этим контрактом не рассчитывается. Ответы политик возвратов/жалоб содержат шаги подготовки обращения; они не создают заявку и не одобряют выплату.
