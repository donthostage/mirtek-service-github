# Сравнение моделей

Подготовлен scripts/compare_models.py. По умолчанию это dry run: он показывает выбранные модели и верхнюю границу числа запросов, не создаёт HTTP-клиенты и не обращается к провайдеру. В репозитории нет реальных ключей и выбранной «лучшей» модели.

Выбрать точные id моделей с поддержкой JSON Schema из каталога AITUNNEL. После согласования бюджета и скрытого ввода ключа в серверное окружение можно выполнить ограниченную проверку. Источник моков должен работать на 8767. Пример dry run:

```powershell
.\.venv\Scripts\python.exe -m scripts.compare_models --models MODEL_A MODEL_B --output work/model-comparison.json
```

MODEL_A и MODEL_B — placeholders, их нужно заменить настоящими id. Для платного исполнения той же команды добавить --run. Верхняя граница по умолчанию 10 запросов; первые три диалога требуют максимум 8 для двух моделей. Если план превышает --max-requests или ключ отсутствует, выполнение прекращается до сетевых вызовов модели.

Ограничение числа запросов не является рублёвым бюджетом. Текущий скрипт не получает cost из провайдера: cost_rub=null означает неизвестную стоимость, а не бесплатность. Расход нужно сверить в кабинете/статистике отдельного ограниченного ключа. Модель и бюджет не выбираем без данных о допустимых расходах.

data/model-evaluation.json содержит пять открытых синтетических диалогов. Скрипт сравнивает статус, сценарий, причину и ожидаемый id источника, записывает полные ответы и задержку. При обрыве уточнения оставшиеся шаги помечаются пропущенными и несовпавшими, не исчезают из результатов. Нельзя интерпретировать этот небольшой открытый набор как реальный KPI или закрытый контроль.

Дальнейшая оценка должна включать реальные обезличенные обращения, экспертное подтверждение фактов и независимые данные, которых не было в настройке. Выбор модели делаем по качеству, корректной автоматизации, задержке и фактическим расходам; наличие валидного JSON само по себе недостаточно.
