# Сверка с заданием и состоянием реализации

Дата 23.10.2026. Проверка завершения пока не пройдена. Отдельный работающий фрагмент или зелёные автотесты не подтверждают готовность всего кейса.

1. **Приём свободного текста через независимый от каналов API.** Реализован POST /api/v1/messages, Pydantic-валидация, UUID запроса, контекст. Проверяется tests/test_service.py, test_source_api.py. Интеграции с внешними каналами отсутствуют и не входят в объём PDF.
2. **Понимание разных формулировок без ручного перечисления всех фраз.** Подключён семантический адаптер AITUNNEL с извлечением параметров; baseline явно отделён. tests/test_semantic_flow.py проверяет серверную обработку заданных модельных ответов. Живое качество выбранной модели ещё не подтверждено: ключ и модель не настроены. Требование в части реального качества не завершено.
3. **Минимум пять сценариев.** В runtime представлены шесть предварительных направлений: возвраты, жалобы, наличие, режим работы, акции, доставка/самовывоз. Приоритет первых двух подтверждён пользователем по заказчику. Основной runtime читает все шесть из HTTP-мока шлюза. Окончательный выбор по реальным обращениям ещё не выполнен: обезличенные диалоги заказчик не передал.
4. **Получение данных из источников.** Исходящий read-only HTTP-клиент, предлагаемые API-контракты, отдельный запускаемый мок и снимки реализованы. Источники компании пока заменены моками, что допускается PDF и ответом заказчика. Реального подключения не заявляем.
5. **Достоверность и отказ от выдуманных фактов.** Числа и тексты ответа берутся из источника; схема, параметры, область действия и время актуальности проверяются. Есть тесты отрицательного/неизвестного остатка, чужого склада, устаревания, отсутствующего и некорректного источника. Это проверка программных ограничений; фактическая применимость к данным компании потребует утверждённых правил.
6. **Оператор при невозможности достоверного ответа.** Реализован статус handoff с причиной. Личные решения и связанные темы передаются как пакет утверждений клиента. handoff_delivered=false, регистрации и доставки сообщения нет. По PDF API обязан вернуть признак участия оператора; отдельная интеграция доставки не требуется без расширения задания.
7. **Демоинтерфейс.** Есть ввод, ответ, три статуса, источники и raw JSON. Загрузка актуальной версии 0.4 проверена в браузере; реальные LLM-диалоги пока не проверены. Полной проверки всех экранных размеров нет.
8. **Запускаемый исходный код и документация.** FastAPI-сервис, мок, launcher для двух процессов, зафиксированные зависимости, README, архитектура, API/OpenAPI, JSON Schema и инструкции присутствуют. Полный запуск последней версии и проверка упаковки должны фиксироваться в VERIFICATION.md. Локальный Git-репозиторий создан; bundle экспортируется в комплект передачи без внешней публикации.
9. **Автотесты и тестовая выборка.** tests/ содержит регрессии API, источников, контекста и семантического контракта. data/evaluation.json — открытая синтетическая выборка старого baseline, а не закрытый контроль. tests/test_semantic_flow.py использует вручную заданные разборы. Дополнительно data/workflow-evaluation.json и scripts/evaluate_workflows проверяют 32 диалога/36 шагов актуального потока по шести направлениям. Реальная контрольная выборка отсутствует.
10. **KPI из PDF.** Пороги: ≥90% корректных решений, ≥90% фактически верных автоматических ответов, ≥95% запросов до 5 с, ≥80% автоматизации в поддержанных сценариях. Ни один реальный KPI пока не подтверждён. Отчёт synthetic-report описывает лишь открытый baseline; автотесты и локальный smoke его не заменяют. Методика для согласования — ACCEPTANCE.md.
11. **Сравнение AI-подходов.** Обосновано разделение LLM и программного чтения фактов, отказ от собственной модели и лишней инфраструктуры. Эмпирическое сравнение выбранных моделей по качеству, стоимости и задержке ещё не проведено. Нужны доступ и ограниченный бюджет испытаний.
12. **Данные и неочевидные решения.** OPEN_QUESTIONS.md отделяет подтверждённые решения, настоящие вопросы заказчику и временные моки. Нет необходимости ждать ответов, чтобы завершать программную часть; однако фактическую приёмку и качество на клиентах нельзя заменить вымышленными результатами.
